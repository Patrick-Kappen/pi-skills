# 6. Pull request and handover

1. Push the branch and open a PR. Title: the commit message. Body:
   - **What**: the job, the triggers, and the structure (files and scripts);
   - **Why**: the user's need, and sources used;
   - **Checks**: `check-skills`, `devenv test`, and how you tried it (step 5.3).
2. Watch CI (`gh pr checks <n> --watch`) and fix failures on the branch.
3. Tell the user:
   - the PR link, and that they merge it;
   - that release-please then updates its release PR; merging that one releases the skill;
   - that the skill loads only after the release and a line in nixos-config, in
     `packages/agents/pi/skills/default.nix`:
     `skills.<name>.repos = [ "*" ];` (or the repositories from step 1), plus
     `nix flake update pi-skills`, in a worktree with a PR, then a switch;
   - for an import: which old copy to delete after the switch, so pi does not load it twice.
