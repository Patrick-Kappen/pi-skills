# 6. Pull request and handover

1. Open the PR from the worktree (git skill; `git_pr` where available, else the platform's PR
   tool). Title in the repository's style, for example
   `test: run the test files in parallel and batch Bicep calls`. Body:
   - what changed, one line per technique;
   - the table from `compare-timings.sh` and the time of `just test` before and after;
   - the equal counts and the breaks that failed as expected (step 5).
2. The user reviews and merges. Do not merge.
3. After the merge, tell everyone who runs the tests: update agent briefings, `AGENTS.md`-style
   notes outside git, and running sub-agents with the new commands (`just test-changed` while
   working, `just test` before done). Worktrees branched before the merge only get the speedup
   after they take in the base branch.

**Result:** the PR link, the before/after numbers, and the list of places told about the new
commands.
