# 6. Pull requests and handover

1. Push each branch and open its PR. Title: the commit message. Body:
   - **Why**: the sessions analysed (count, period) and the problems or lessons, without digest
     content;
   - **Changes**: per change, the file and what changed;
   - **Not changed**: items you dropped, and why;
   - **Checks**: `check-skills` and `devenv test` (or the repository's checks).
   Mention the related PRs of the same review in each body.
2. Watch CI (`gh pr checks <n> --watch`) and fix failures on the branch.
3. Tell the user:
   - the PR links, and that they merge them;
   - that release-please then updates its release PR in each repository; merging that one
     releases;
   - that the machine gets it after the release, by updating the flake input (`pi-skills`,
     `pi-rules`) in nixos-config (`nix flake update <input>` in a worktree, then a PR) and switching;
   - the proposed nixos-config lines for permissions, hooks or where a rule applies, if any;
   - where the report is (`<dir>/report.md`), and the open questions from it.
4. Leave the digests in place; they are in the user's cache directory. Delete them if the user asks.
