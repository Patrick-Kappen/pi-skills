# 6. Pull request and handover

1. Push the branch and open a PR. Title: the commit message. Body:
   - **Why**: the sessions analysed (count, period) and the problems found, without digest content;
   - **Changes**: per change, the file and what changed;
   - **Not changed**: findings you dropped, and why;
   - **Checks**: `check-skills` and `devenv test`.
2. Watch CI (`gh pr checks <n> --watch`) and fix failures on the branch.
3. Tell the user:
   - the PR link, and that they merge it;
   - that release-please then updates its release PR; merging that one releases the new version;
   - that the machine gets it after the release, by updating the `pi-skills` flake input in
     nixos-config (`nix flake update pi-skills` in a worktree, then a PR) and switching;
   - where the report is (`<dir>/report.md`), and the open questions from it.
4. Leave the digests in place; they are in the user's cache directory. Delete them if the user asks.
